# الهيكل البرمجي

## طبقات المشروع

- `ui`: واجهات Compose، التنقل، نظام التصميم، ViewModel وحالة الواجهة.
- `data/vehicle`: نموذج القراءة الموحد، موفّرات البيانات و`VehicleDataManager`.
- `data/local`: Room لبيانات الرحلات والصيانة وDataStore للتفضيلات.
- `diagnostics`: فحص النظام والتطبيقات والمزايا والصلاحيات.

## نموذج القراءة

كل قيمة مركبة داخل `Reading<T>` وتحتوي على:

- القيمة أو `null` عند عدم توفرها.
- مصدر القراءة.
- وقت آخر تحديث.
- مدة الصلاحية قبل اعتبارها قديمة.

لا يحوّل التطبيق القراءة غير المتاحة إلى صفر. الواجهة تعرض `—` بوضوح.

## ترتيب المصادر

يختار `VehicleDataManager` القراءة الأعلى أولوية:

1. GWM.
2. Android Automotive.
3. GPS.
4. OBD-II.

الوضع التجريبي مسار مستقل ويظهر بشارة برتقالية دائمة. عند إيقافه تُحذف قيم المحاكاة فورًا.

## تكامل GWM

لا يعتمد المشروع على كود أو ملفات ثنائية من `H9-cluster`. الموفر الحالي فحص آمن لحزمة `com.gwm.android.adapter.server`. إضافة Binder/AIDL تتطلب معرفة العقد الفعلي والصلاحيات على شاشة السيارة؛ يمنع تخمين معاملات الخدمات أو إرسال أوامر كتابة.
